合集池新增OPPO类型短剧主动推送 · V1.0

# 页面说明

  • 菜单路径：绿台 ＞ 产品运营 ＞ 内容运营 ＞ 合集池管理
  • 使用对象：内容业务、渠道运营
  • 参考文档：OPPO短剧标准接入文档forCP-主动推送
  • 需求背景：绿台需要通过OPPO主动推送接口同步短剧及剧集，合集池新增“OPPO”类型，用于维护待推送内容范围。
  • 需求目标：完成建池、选剧、校验、推送、结果回查和失败重试闭环。

# 页面改动

筛选与列表

  • 池类型：新增枚举“OPPO”，后端枚举值为oppo。
  • OPPO池操作：保留修改名称、修改池元素，新增“OPPO推送、推送记录”。
  • 池元素数：展示池内有效合集数量，删除或新增元素后实时更新。

新建合集池

  • 池名称：必填，建议体现渠道及内容范围。
  • 池类型：必填，选择OPPO后创建OPPO专属池。
  • 状态：默认启用；停用后不允许发起推送。

池元素管理

  • 校验状态：可推送、校验失败、已推送、推送失败。
  • 推送前校验：检查短剧主信息、全部剧集信息、ID、图片、视频和枚举映射。
  • 查看问题：展示缺失字段或不符合OPPO规范的具体原因。

# 推送流程

  1. 业务维护OPPO合集池及池元素。
  2. 系统执行推送前校验，仅校验通过的内容可推送。
  3. 调用“添加或更新短剧”接口推送短剧主信息。
  4. 主信息成功后调用“添加或更新剧集”，每部短剧每次全量推送全部剧集。
  5. 解析成功及失败列表，记录到推送批次；失败内容支持单独重试。
  6. 上下架变更通过短剧状态接口同步；分类接口按全量分类数据同步。

# 字段规则

短剧必填

短剧ID、标题、简介、分类、更新状态、总集数、封面、更新时间、短剧类型、内容形态、二级分类、制片人、导演、演员、平均集时长、版权方、投资额、编剧。

短剧非必填

上下架状态、跳转链接/跳转数组、标签、节目评分、节目热度。

节目评分、节目热度、一句话推荐语、跳转数组及三方短剧枚举在接口文档中标记为“即将上线”，研发接入前需与OPPO确认生产环境生效时间。

剧集必填

剧集ID、标题、集序、封面、更新时间、播放地址、视频时长、宽度、高度、文件大小。

系统参数

partnerId、timeStamp、nonce、sign、reqBody均由服务端生成，业务端不展示、不填写。

# 校验口径

  • ID：短剧ID、剧集ID全局唯一，不含特殊符号，长度不超过16位。
  • 文本：标题不超过64字符，简介不超过2000字符。
  • 封面：3:4竖图，使用稳定图片地址，不拼接动态参数。
  • 视频：清晰度不低于720p；使用OPPO承载时需MP4，单集文件不低于50MB。
  • 集数：总集数必须与全量剧集数量一致，集序从1开始且连续。
  • 批量：短剧主信息接口单次不超过100部；整体批量不超过300部，系统按100部拆批。

# 状态与异常

  • 推送状态：未推送、推送中、推送成功、部分失败、推送失败。
  • 短剧状态：up上架、down下架、waiting待上架。
  • 失败处理：保留OPPO返回的失败ID及原因；重试仅提交失败项，剧集重试仍需全量。
  • 幂等更新：同一短剧ID或剧集ID再次推送视为更新，不新增重复内容。

# 本期范围

  • 本期包含短剧、剧集、分类和状态推送。
  • 榜单接口已预留数据结构，是否由合集池顺序直接生成榜单需业务与OPPO确认后另行启用。
  • OPPO鉴权密钥、生产域名及签名逻辑由服务端配置，不进入绿台页面。
