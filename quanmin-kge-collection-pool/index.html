# 页面说明

  • 菜单路径：绿台 ＞ 产品运营 ＞ 内容运营 ＞ 合集池管理。
  • 使用对象：内容业务、渠道运营，沿用现有合集池权限。
  • 需求目标：新增全民K歌池，完成选剧、资料维护、校验、推送及结果追踪。
  • 参考资料：OPPO合集池原型、声播统一接入内容合作API—短剧。
  • 接入前提：接口文档未明确列出全民K歌，须确认账号分发渠道与授权范围，确认前不开放正式推送。

# 页面改动

筛选与列表

  • 池类型：新增“全民K歌”，保留OPPO及其他类型；池ID、名称、状态筛选不变。
  • 行操作：保留“修改名称、修改池元素、自动添加元素、更多”及现有顺序。
  • 新建池：名称、类型必填，状态默认启用，创建后元素数为0。

池元素管理

  • 展示合集ID、名称、总集数、校验状态、推送状态、最近推送时间；支持添加元素、维护渠道资料、查看问题及推送记录。
  • 自动添加沿用现有选剧规则、执行方式与同池去重，仅维护池内范围，不自动发起推送。
  • 停用池禁止新推送；移除元素、停用或删除池均不等于平台下架，历史记录保留。

# 推送流程

  1. 维护合集及渠道资料，执行校验；缺失字段可定位到合集或具体分集。
  2. 确认本次范围及跳过数量，仅提交校验通过的内容；提交前服务端再次校验。
  3. 先提交专辑，成功后提交其分集；一部合集对应一个专辑，ID保持稳定。
  4. 每次请求最多提交同一专辑的100条分集，不限制该专辑总集数；如125集拆为100+25条，保留原集序并逐项记录结果。
  5. 新增及更新内容标记待同步，由运营确认提交；调序、付费变更使用独立接口并留痕。

# 字段规则

专辑资料

必填：唯一ID、名称、封面及MD5、简介、演员/角色、备案信息、内容类型、一级/二级分类、发布时间、是否首发、全网发布时间。类型区分漫剧、短剧、儿童，分类按平台枚举映射。

备案材料

  • 制作预算必填，单位万元，整数1～999999；成本配置证明始终必填。
  • 仅短剧类型（type=2）必填演员总片酬占比，范围1%～99%、两位小数；例如18.35表示18.35%，不是金额。
  • 预算≥100万元时，须补充广电备案号、上线备案材料；100万元边界待平台确认。

分集与付费

分集唯一ID、视频MD5必填。本期首传或替换视频须提供下载地址，并传真实集序。付费接口列出免费、单集付费、整剧付费、各平台自定四种模式；账号可用模式及字段约束须确认，价格、会员及起付集数不按示例自动赋值。

MD5及鉴权由服务端处理，运营无需填写签名或密钥。

# 校验口径

  • 完整性：校验必填、条件必填、有效分类、重复ID及集序；资料变更后重新校验。
  • 视频：下载地址长度≤512，至少可访问7日；不继承OPPO的720p、50MB限制。
  • 封面：专辑字段要求3:4且大于600×800；通用标准要求方图最低750×750、推荐1500×1500且带标题。两处冲突，最终规格须平台确认后启用校验。
  • 分批：100条限制针对单专辑分集，不是100部合集；分批不重新编号。
  • 定时：定时发布时间须首次推送携带；时区、即时发布取值及后续改期规则待确认。
  • 未确认配置：渠道权限、分类映射及商业配置未确认时提示原因，不允许用占位值提交。

# 状态与异常

  • 校验状态：未校验、校验通过、校验失败；与推送状态分别展示。
  • 推送状态：未推送、推送中、推送成功、部分失败、推送失败、结果待确认、已中止。中止时未发送项记已取消，已发送项保留实际结果；存在不确定结果时优先显示待确认。
  • 成功口径：依据专辑及各分集实际响应，顶层成功不代表全部分集成功，也不保证已分发至全民K歌、审核通过或已上架。
  • 异常处理：明确失败记录原因并支持修正后重试；超时或结果不完整进入待确认，不自动反复提交。增量及重试语义须联调确认。
  • 清空资料：可选字段的省略、null、空值处理须确认；确认前不把本地清空记为平台已清空。
  • 记录：保留批次、时间、操作人、合集及分集结果；调序和付费变更单独记录。
