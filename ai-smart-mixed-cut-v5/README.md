## 建议体验

1. 默认高光混剪、前 30 集，查看“复用 10 集、新增分析 20 集”；进入内容方案，检查剧情方向、开头、结尾与来源。勾选两条可比较原片重合情况，先试一条后可继续剩余方案。
2. 切换 AI 解说，明确选择“解说＋原片”或“全解说”。混合结构分别设置成片时长、解说总时长及位置；两种解说结构均可独立选择解说语速，目标时长按变速后计算。全解说按目标成片时长组织完整叙事，不默认短解说，也不保留原片人声。
3. 试制全解说后，在“图文对应”定位原片依据，在“全文与包装”分段修改全文。切换页签会保留未保存草稿；保存后升级内容版本并重新确认，也可放弃草稿。
4. 将条数设为 20，或使用较少剧集选择较长成片，查看候选不足与零候选状态。只按可用且勾选的方案制作，不重复素材凑条数或时长。
5. 检查成片并标记问题：高光／混合结构可体验对白、铺垫与配乐修复；全解说可体验句子完整性、图文对应与配乐修复。修改后需重新确认。
6. 人工确认后同步。国内／海外绿台自动选择对应系统，手动片源先选择目标；单条入口默认上传当前成片，批量入口沿用已选成片，弹窗不再设置上传区域。填写五项必填信息，并注意上线时间对素材保护规则的影响。可演示部分失败重试与未知结果查询。
7. 在“剧目与剧情”新增国内／海外合集，同剧多批次集中展示；在“任务与成片”跨剧筛选并直接展开成片，生成后自动展开新任务，不经过单独的批次结果页。在“积分与用量”查看分析、冻结、结算、失败释放和每条可用素材消费。

## 本版核心能力

- 片源：国内和海外独立绿台合集列表、搜索和起止选集、缺集校验；本地视频仅预览，另提供类型未知的手动示例流程。
- 多剧管理：来源系统＋合集确定剧目身份，同剧多批次聚合；不同手动示例使用独立身份。旧任务自动归入剧目库，不按剧名合并。按当前原片版本和语言显示分析数量，当前成片版本统计确认与同步。
- 剧情资产：按“来源系统＋合集＋原片版本＋语言”隔离缓存；逐集显示分析状态，查看人物／事件／对白时间码；人物纠正生成新的分析版本。
- 高光混剪：提炼冲突，保留必要铺垫与完整对白；冲突前置时明确标记“稍早”背景。问句和回答构成不可拆的示例单元。
- AI 解说支持两种明确选择的结构：`mixed` 为“解说＋原片”，文案依据接入片段创作，再接完整原声；`full` 为“全解说”，分段文案贯穿全片，对应原片画面，原片人声关闭。完整结构、文案编辑及问题反馈随结构变化。
- 解说语速独立于原片速度，可选 0.8/1/1.1/1.2/1.5×，默认 1×。按变速后的目标时长规划文案；全解说不受隐藏的原片速度影响。
- 制作页移除个人预设和独立的“配乐与标题”配置入口；勾选 BGM 即打开曲目选择，确认后启用、取消保持原状态；勾选引流小标题立即输入，开启时必填且最多 24 字。右侧实时显示结构、语速、字幕、BGM 与标题。
- 任务卡片直接展开成片，保留进度、补生成、检查、批量确认、同步及导出；一次展开一个任务，切换时清空跨批次选择。
- 全解说草稿按成片保存，切换页签或刷新可继续编辑；保存全文后清除草稿、升级版本并撤销旧确认。未保存草稿会拦截确认、同步、导出、试听和修复，用户可保存或放弃。文案修改后的配音时长、字幕和画面需要重新检查。
- 旧原片任务及原费率保留；“再做一批”转入高光混剪。旧版未明确结构的 AI 解说方案需重新选择结构，不静默视为短解说。
- 选集仅覆盖事件一部分时，标题、冲突和结尾依据实际保留剧情，不引用范围外结论。
- 批量方案先整理后制作，可直接生成或先试一条；同一计划中已制作方向不重复追加。候选不足时说明可用数量，零候选时引导调整选集或时长。
- 多版本质量与交付：技术检查不自动确认为业务可用；系统修复不重复扣示例积分，修改后旧素材不被静默覆盖或撤回。
- 默认制作标准在生成流程中执行，历史任务保留规则快照；剪辑前台不再提供标准配置菜单或发布/回退入口。质量问题继续随成片保存。
- 导出带来源、分析、标准和版本的 JSON，以及当前故事板的 SRT 示例字幕。无 MP4。

## 演示边界

用户已确认投放回传评分放到下一版：当前没有效果回传、综合评分和基于投放数据的策略优化入口。

所有剧集、人物、对白时间码、分析、生成、质检和同步均为虚构演示。未接入真实绿台、AI、配音、视频渲染或投放系统；不读取或上传真实视频。本地文件只作浏览器预览，不套用示例剧情。封面为已有虚构剧照，播放器按故事板计时，无真实原片音轨。

字幕时间码为故事板段落示意，不代表实际口播对齐。人物纠正仅模拟称呼修订，不能据此评估真实识别质量。当前未演示真实模型的分析失败恢复、跨设备任务持续执行或企业权限。

计费仅为交互演示假设，不是正式报价：

- 100 积分 = 1 元；新增分析 1 分／集。
- 高光混剪 32 分／条；解说＋原片 50 分／条。
- 全解说每条为 `32 + ceil(计划目标解说秒数 / 30) × 18` 积分；按所选时长对应的计划目标计算，费用明细展示分项。
- 原片混剪 28 分／条仅用于历史任务，不是当前默认制作方式或新制作费率。
- 分析完成即结算；制作先冻结，再按成功条目结算，失败释放。只做分析也产生对应示例消费，复用不重复收分析费；系统问题修复与素材同步不重复收费。默认前 10 集为免费预置分析样例。

每条可用消费按已结算示例积分÷100÷当前版本已确认可用条数计算，零条显示“暂无可用成本”；这是消费口径，不是内部全链路成本。真实模型、合成、重试、存储和人工返工费用尚无数据，不能宣称0.6元目标已达成。

同批重合度按原片时间范围计算。高光与混合结构的 5 组虚构事件 × 3 个方向最多提供 15 个初始候选，过滤后可能更少；全解说按所选剧情及目标时长整理候选。候选数量是样例限制，不是对真实系统产能的承诺，也不保证方案均可投放。约 1 分钟的原片类成片范围允许 45–80 秒，以保留完整语义单元。

前端使用独立 localStorage 键 mixed-cut-v5-demo。刷新会将未完成模拟生成标为失败并释放冻结积分；同步未完成转为待核实，避免自动重复上传。真实生产需服务端任务与幂等保障。

## 验证

- 2026-09-16：混合/全解说 × 5 种语速的 10 组配置验证目标时长、方案与批次快照、成功结算和失败释放；验证标题必填/字数限制、转义及原片字幕保留。15 个 JavaScript 模块语法通过。
- 本轮浏览器走通 BGM 选择/取消、标题即时预览、解说与原片独立速度、生成直达任务、成片检查后返回、任务筛选空状态、批量确认和手动片源同步目标选择（未提交同步）；对应编号说明联动正常。
- 2026-09-15 完成 7,337 项断言，覆盖制作结构、来源范围、时间线、计费和版本状态等逻辑。检查对象是 Demo 数据与交互，不是 AI 模型质量。
- 全解说：明确选择结构与时长、生成、图文定位、全文编辑、草稿保留、保存后版本重新确认、问题修复及同步。
- 混合解说：部分生成失败、失败额度释放、仅补生成失败条目；高光／混合已有的对白、铺垫和配乐修复链路保持可用。
- 兼容与边界：历史任务再次制作转为高光，旧内容与同步记录保留；候选不足及零候选时不伪造成功；多剧归档、筛选、版本确认及同步关联继续有效。
- 播放状态：切换成片重置位置，同片重绘保持位置，播放结束后可重播；未保存文案不因切换检查页签丢失。
- 已检查 1280×800、1440×900、1920×1080 三个桌面尺寸。分析、生成、修复与同步均为交互验证，未验证真实视频质量或实际成本。
- 若浏览器支持 WebMCP，提供读取当前演示状态、配置并整理示例方案两个入口；有效／无效输入已通过浏览器工具验证，与可见界面使用相同操作。

## 文件结构

- index.html / styles.css：工作台界面与全局演示提示。
- app.js：页面与交互、任务、质量反馈和示例账本。
- creation-ui.js：两个制作入口、解说结构选择、制作参数与实时结构预览。
- tasks-ui.js：跨剧任务卡片与展开成片列表。
- full-narration.js / narration-ui.js / narration.css：全解说方案、图文对应、全文编辑与检查界面。
- dramas.js / library-ui.js / library.css：剧目聚合模型、列表/详情/任务筛选与布局。
- engine.js：方案编排、来源范围、缓存键、计费与版本纯逻辑。
- story-data.js / sources.js：虚构剧情与两套合集样例。
- sync-model.js / sync-ui.js / sync.css：沿用 V4 的素材交付流程。
- assets/drama-confrontation.jpg：虚构剧照。

## 原型说明文件

- `review.html` / `review.css` / `review.js`：左右对照评审页。
- `review-notes.js`：各页面与弹窗的编号需求说明及对应区域。
- `review-bridge.js` / `review-annotations.css`：仅在嵌入评审模式启用编号及定位，独立 Demo 保持原操作。
- `PRD.md` / `prd.html`：完整 PRD；执行 `python3 build-prd.py` 从目录内 PRD.md 重新生成；也可通过 `--source <Markdown路径>` 使用工作区主文档。页面需求变更时同步更新编号说明与完整 PRD。

- `build-prd.py` / `prd-renderer.py`：可独立运行的 PRD 构建脚本与渲染器，仅使用 Python 3 标准库。
