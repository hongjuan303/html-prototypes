短剧推广计划功能优化

将分散在各小程序后台的推广计划操作统一收口至绿台，并保证状态、数量与操作记录可追溯。

使用对象：视频号原生运营、内容业务更新时间：2026-09-01

# 页面说明

菜单路径：绿台 ＞ 内容管理 ＞ 短剧推广计划

业务背景：运营当前需扫码登录多个媒资小程序后台添加或退出推广计划，操作分散、效率低，且小程序后台缺少人员操作记录，出现问题后难以追溯。

需求目标：统一推广计划入口，复用送审数据判断准入资格，记录完整操作链路，并与微信小程序后台保持数据一致。

# 架构逻辑

微信送审库审核结果、小程序枚举
→
推广计划服务准入校验、状态流转、操作编排
→
微信小程序后台加入/退出结果、合作剧目数
操作日志：记录操作人、时间、前后状态、请求结果 对账任务：按小程序校验已加入条数与“总合作剧目数”
  1. 统一数据口径：以“小程序＋合集ID”为唯一推广单元；小程序枚举与“内容审核库-微信送审库”的“送审小程序”共用同一数据源。
  2. 准入前置：实时读取媒资审核、剧目审核结果，仅两者均为“审核通过”时允许加入。
  3. 指令下发：绿台按小程序路由加入/退出指令；批量任务按小程序分组执行，单条失败不阻断其他记录。
  4. 状态回写：接口成功后回写推广状态与操作留痕；微信侧异步退出时先展示“退出计划中”。
  5. 同步对账：小程序后台为推广状态最终事实源；操作后即时同步，并通过定时任务校正状态及已加入数量。

# 原型说明

1筛选项

  • 合集名称：文本输入，支持模糊搜索。
  • 合集ID、剧目ID：精确搜索；点击“录入”后支持多个ID批量粘贴，每行一个，交互与微信送审库一致。
  • 小程序：单选；枚举与微信送审库“送审小程序”一致，后续增删自动同步。
  • 推广状态：全部、未加入计划、已加入计划、退出计划中。

2列表字段

合集ID、合集名称、剧目ID、小程序、媒资审核状态、剧目审核状态、推广状态、推广备注、操作人、操作时间、操作。

审核未全部通过的记录仍可查看，但复选框与加入操作禁用，并在备注中展示未满足原因。

3加入与批量加入

  • 仅“未加入计划”且媒资、剧目审核全部通过的数据可加入。
  • 批量加入支持跨小程序选择，由系统按小程序拆分任务。
  • 提交前再次校验准入条件与当前状态，避免审核状态变化或重复加入。
  • 部分失败时成功项正常回写；失败项保留原状态，并记录失败原因。

4退出计划

已加入计划的数据可执行退出。确认后状态更新为“退出计划中”；收到微信侧成功结果后切换为“未加入计划”。退出失败则恢复“已加入计划”并写入推广备注。

5操作留痕

成功提交加入或退出指令后，记录操作人、操作时间、操作类型、操作前状态、操作后状态、请求流水号及接口结果。列表展示最近一次操作人和操作时间。

# 状态与规则

未加入计划加入成功 →已加入计划提交退出 →退出计划中退出成功 →未加入计划
幂等键：小程序 AppID ＋ 合集ID ＋ 操作类型。重复请求不重复执行，直接返回已有任务结果。
异常规则：超时不直接判定失败，推广状态保持操作前状态，仅在推广备注标记“结果待同步”并主动查询微信侧；最终状态以微信小程序后台为准。

# 数据一致性

  • 筛选某一小程序及“已加入计划”时，列表条数必须与该小程序后台“总合作剧目数”一致。
  • 加入/退出后立即触发单条同步；定时任务按小程序进行全量对账。
  • 发现数量不一致时生成差异明细，记录小程序、合集ID、两端状态、发现时间与修复结果。
  • 对账未完成前不覆盖人工操作日志，仅修正推广状态及同步备注。

# 验收标准

  1. 双审核通过的数据可单条或批量加入；任一审核未通过的数据不可加入。
  2. 合集ID、剧目ID可一次录入多个值并精确命中；其他筛选组合生效。
  3. 推广状态只展示三个业务枚举，不再混用“审核通过”等审核状态文案。
  4. 加入、退出均有二次确认；操作完成后状态、操作人和时间正确回写。
  5. 按小程序筛选已加入计划时，条数与微信后台总合作剧目数一致。
  6. 所有失败、超时、重复请求均有明确结果和可追溯记录。
